# FedG2C 组合器逐步解读

核对日期：2026-10-14。依据当前 composer.py、SharedBackbone、NodewisePredictionModel、ProbeEvaluator、TargetModel 及默认配置。本文说明现有代码的计算，不把结构组合泛化作为已验证结果。

## 1. 一句话定位

RelationComposer 接在多个共享图专家之后，把“每个节点的多个专家表示”转换为“每个节点的一份组合表示”。它属于共享基座，与专家一起预训练、上传、聚合并进入目标域。

默认接口：

~~~python
z = composer(expert_repr, relations)
z, code = composer(expert_repr, relations, return_routing=True)
~~~

它处理的是单个局部视图／单张图，而不是直接处理整个联邦客户端集合。一次前向没有 batch 轴。

## 2. 在三个阶段中的位置

### A：本地预训练

~~~text
当前可见局部图
  → 私有节点／可选边输入适配器
  → M 个共享图专家
  → expert_repr [N,M,d]
  ＋ 当前可见边生成的 relations [N,N,3]
  → RelationComposer
  → z [N,d]
  → RWSE＋GraphSAGE 预测器
  → 预测位置上的潜表示
  → 对照完整局部图的 EMA 参考表示计算 SmoothL1
~~~

[SharedBackbone.forward](../fedg2c/model.py) 的三个直接步骤是：encode_experts → structural_relations → composer。

[NodewisePredictionModel.forward](../fedg2c/edge_model.py) 中，主分支与 EMA 参考分支都有专家和组合器。主分支读受扰动图并接收梯度；参考分支读完整局部图，只由 EMA 更新。RWSE 送入组合器之后的预测器，没有直接送入组合器 Q/K。

组合器本身不做遮边、不确定预测索引、不计算预训练损失。它通过外部预测损失获得训练信号。只有主分支共享专家与完整组合器上传；预测器、适配器和 EMA 留在本地。

### B：服务器聚合

~~~text
合成探针图＋d 维高斯特征
  → 共享专家编码一次，得到 H
  → 相同 H、R 多次调用组合器，改变 relation_gate
  → z [N,d]
  → 固定节点对的余弦相似度读数
  → 比较基准输出与有限差分响应
  → 优化客户端聚合权重
~~~

[ProbeEvaluator.forward](../fedg2c/server_probes.py) 复用专家输出，分别传入 g=1、g=1+εδ、g=1−εδ。只变化组合器内部的关系偏置乘法门控；图边、输入、专家表示和关系描述固定。

服务器优化的是客户端参数混合权重，而不是脱离客户端上传参数重新训练一个自由组合器。上传与聚合的状态包括整个 composer.*，关系映射也在内。

### C：目标域微调

~~~text
目标图／节点邻域
  → 新目标输入适配器
  → 冻结专家
  → [可选 prompt：H+p]
  → 原共享组合器
  → [可选 adapter：组合输出后残差]
  → [可选本地编码分支融合]
  → 中心节点读出，或整图节点均值池化
  → 新任务头
~~~

[TargetModel.forward](../fedg2c/target_model.py) 保留组合器原参数，按模式改变适应位置：
- none：只训练新的输入适配器与任务头。
- lora：在组合器 Q/K 添加低秩增量；原权重、关系映射、V、输出映射与归一化冻结。
- prompt：所有节点、所有专家表示共同加同一个向量，再进入组合器。
- adapter：组合器输出之后增加瓶颈残差。

三种额外适应方式互斥。固定本地权重 α=1 时共享分支被跳过，是一个例外对照。

## 3. 输入、输出和符号

为避免专家表示 H 与注意力头数混淆，本文用 J 表示 num_heads。

| 符号 | 含义 | 默认值／形状 |
|---|---|---|
| N | 当前视图的节点数；代码局部变量 p | 本地预训练最多 32 |
| M | num_experts，独立图专家数量 | 4 |
| d | hidden_dim，专家输出及最终节点表示维度 | 64 |
| J | num_heads，组合器的注意力头数 | 4 |
| d_h | 每头维度；代码 self.depth | d/J=16 |
| L | 展开后的 token 数 | N×M |

M 和 J 是不同轴：专家是不同图编码器，头是 Q/K/V 投影后拆出的子空间。默认都等于 4，不代表每个头专门对应一个专家。self.depth 是每头特征维度，不是网络层数。

### expert_repr

形状 [N,M,d]。H[u,m,:] 是节点 u 在专家 m 下的 d 维表示。它已包含专家对输入特征、拓扑及可选边属性的编码。

组合器不直接接收原始 x、edge_index、edge_attr 或标签。边属性只能先经专家影响 H；它不是当前三维 relations 的组成。

### relations

形状 [N,N,3]，在组合器外由 [structural_relations](../fedg2c/context.py) 构造：

\[
r_{uv}=[I_{uv},A_{uv},\mathbf1((A^2)_{uv}>0)].
\]

A 的重复边二值化，有向图保留方向；两步可达不是“最短距离恰好为 2”。三通道可以重叠。例如无向链 A—B—C：

| 节点对 | 关系 |
|---|---|
| A,A | [1,0,1]，通过 B 可以两步回到自身 |
| A,B | [0,1,0] |
| A,C | [0,0,1] |

这些是拓扑描述，不是语义因素标签。

### relation_gate

可选 [N,N] 矩阵 g。默认 None，不额外缩放关系偏置；传入全 1 与默认功能相同。服务器使用它制造受控的小幅关系条件扰动。

每个 g_uv 共同缩放该节点对的全部头偏置，并重复到全部专家对。它不是注意力掩码，也不屏蔽内容分数。在无关系分支或 linear_gate 模式中没有作用。

### return_routing

默认 False，只返回 z；True 则还返回内部条件编码／门控权重。

| 模式 | 正常输出 | 额外返回 |
|---|---|---|
| hypernetwork_relu / hypernetwork_linear | z [N,d] | code [J,L,L]，允许负值，不是概率 |
| standard_attention | z [N,d] | code [J,L,L]，沿 key 轴 softmax |
| linear_gate | z [N,d] | weights [N,M]，沿专家轴 softmax |

即使关闭关系条件，当前 forward 仍要求 relations 具有正确形状。正常配置在入口检查 d 能被 J 整除，且 linear_gate 要求 relation_condition=false。

z 是逐节点潜表示，既不是类别概率，也不是整图向量。分类头、节点读出和图池化位于组合器外。

## 4. 默认 hypernetwork_relu 的内部计算

### 第一步：展平节点×专家

~~~python
tokens = expert_repr.reshape(N * M, d)
~~~

token 按节点优先排列：

~~~text
(u0,e0), (u0,e1), …, (u0,eM−1),
(u1,e0), (u1,e1), …
~~~

token t=uM+m 表示节点 u 的专家 m 视角。展开不合并信息，只改变索引布局。

### 第二步：共享 Q/K/V 投影并拆头

~~~python
q = self.query(tokens).reshape(L, J, d_h)
k = self.key(tokens).reshape(L, J, d_h)
v = self.value(tokens).reshape(L, J, d_h)
~~~

三个 Linear(d,d) 各自有参数和偏置，所有节点与专家 token 共用各自的投影。不是每个专家另配一套 Q/K/V。

Q 表示查询需求，K 表示可供匹配的内容，V 表示实际参与组合的信息。这是帮助理解映射作用的直觉，不是预定义的专家语义。

### 第三步：内容分数

~~~python
scores = torch.einsum("qhd,khd->hqk", q / math.sqrt(d_h), k)
~~~

\[
S^{content}_{hts}=\frac{Q_{th}^{\top}K_{sh}}{\sqrt{d_h}},
\qquad S^{content}\in\mathbb R^{J\times L\times L}.
\]

这里代码 einsum 中 q/k 是 token 索引、h 是头轴、d 是每头通道索引。输出排列是“头、query token、key token”。

同一节点的不同专家可以交互，不同节点的任意专家也可以交互。

### 第四步：关系偏置

~~~python
bias = self.relation(relations).permute(2,0,1)
scores += bias.repeat_interleave(M,1).repeat_interleave(M,2)
~~~

关系映射为 Linear(3,J,bias=False)。对头 h：

\[
b_h(r_{uv})=
w_{h,self}I_{uv}
+w_{h,edge}A_{uv}
+w_{h,2hop}\mathbf1((A^2)_{uv}>0).
\]

这些系数可学习，符号不限，因此直接相邻不保证得分总是更高。没有截距意味着 r_uv=[0,0,0] 时关系偏置恰为零。

偏置从 [J,N,N] 扩为 [J,L,L]。同一节点对 (u,v) 的全部 M×M 专家组合共享关系偏置，内容分数则可能不同：

\[
S_{h,(u,m),(v,n)}
=S^{content}_{h,(u,m),(v,n)}+g_{uv}b_h(r_{uv}).
\]

不传 gate 时按 g=1 理解。gate 只缩放关系项。

当前 mask 为全 1；没有强制只与直接邻居或两跳节点交互。即使 r_uv=0，内容项也可以造成交互。因此范围是当前有界视图内的密集交互。

### 第五步：沿头轴 RMS 归一化

~~~python
code = scores * torch.rsqrt(
    scores.square().mean(dim=0,keepdim=True)+1e-6
)
~~~

\[
C_{hts}=
\frac{S_{hts}}{\sqrt{J^{-1}\sum_{a=1}^{J}S_{ats}^{2}+\epsilon}}.
\]

对固定 token 对 (t,s)，取 J 个头分数并归一化；没有跨 key 求 softmax。每个 token 对都有自己的分母。

教学算例：两个头分数为 [3,4]，得到约 [0.8485,1.1314]。和不等于 1，值也可超过 1；原分数为负时归一化后仍为负。这一 code 不适合直接解释为专家选择概率。

头轴归一化保留的是不同头之间的相对条件结构，并耦合各头的分数尺度。关系门控改变分数后，还会经过此归一化与后续非线性，所以“提高 g”不保证某个最终贡献单调提高。

### 第六步：第一次收缩，沿头轴混合 Value

~~~python
intermediate = torch.einsum("hqk,khd->qkd", code, value)
~~~

\[
T_{tsc}=\sum_{a=1}^{J}C_{ats}V_{sac},
\qquad T\in\mathbb R^{L\times L\times d_h}.
\]

对每个 query/key token 对，用条件编码把 key token 的多个头 Value 混成一份中间向量。

消掉的是头轴 a；key token 轴 s 此时保留。每个 (t,s) 仍单独有一个向量，尚未汇总所有 key。这与标准注意力直接对 key 求和不同。

随后执行逐元素 ReLU：

\[
\widetilde T_{tsc}=\max(T_{tsc},0).
\]

### 第七步：第二次收缩，沿 key 轴聚合

~~~python
out = torch.einsum("hqk,qkd->qhd", code, intermediate)
~~~

\[
O_{thc}=\sum_{s=1}^{L}C_{hts}\widetilde T_{tsc},
\qquad O\in\mathbb R^{L\times J\times d_h}.
\]

这一步汇总 key token，重新形成每个 query token 的多头输出。同一份 C 前后使用两次，中间有非线性。

两次收缩不是走两跳图路径，也不是串联两层普通注意力。第一步消去头轴，第二步消去 key 轴；“两跳关系”早已在 relations 中单独构造。

将固定 (t,s,c) 的头向量写成 c_ts=C[:,t,s]、v_sc=V[s,:,c]，该节点专家对的条件变换可以写为：

\[
f_{c_{ts}}(v_{sc})
=c_{ts}\operatorname{ReLU}(c_{ts}^{\top}v_{sc}).
\]

它相当于一个 J→1→J 的小型条件网络，输入／输出权重都来自内容与关系生成的 c_ts；每个值通道复用这组条件权重，再把各 s 的贡献求和。这是本代码“超网络”机制的直接数学解释。

若去掉 ReLU，贡献成为 c_ts c_ts^T v_sc。默认加入非线性后，不能再把整体视为一个与 Value 无关的固定加权平均。

教学算例：沿用 c=[0.8485,1.1314]，某个 key 的两个头 Value 为 [2,−1]：
- 第一收缩：约 0.5657。
- ReLU 保留此值。
- 第二收缩：该 key 对两个输出头分别贡献约 [0.48,0.64]。

若 Value 取 [−2,1]，中间值为负，ReLU 将此项贡献变成零。这说明同一份条件编码下，Value 的内容也决定非线性响应。

### 第八步：拼头、输出映射、残差、LayerNorm

~~~python
out = self.norm(tokens+self.output(out.reshape(L,d)))
~~~

先把 J 个头拼接成 d 维，再用 Linear(d,d) 映射：

\[
Y_t=\operatorname{LN}\left(
H_t+W_O\operatorname{concat}_h(O_{th})+b_O
\right).
\]

残差保留原专家 token 信息；输出映射混合多头通道；LayerNorm 按每个 token 的 d 个特征归一化，并有可学习缩放／偏移参数。

没有在节点轴做归一化。当前组合器也不是包含额外 FFN 的完整标准 Transformer block。

### 第九步：只平均同一节点的专家轴

~~~python
z = out.reshape(N,M,d).mean(dim=1)
~~~

\[
z_u=\frac1M\sum_{m=1}^{M}Y_{(u,m)}.
\]

最后虽是等权平均，平均的是已经完成条件交互的 token，不是原始专家输出 H。各 token 在前面已受到不同节点和专家的内容影响。

先对每个 token LayerNorm，再求专家平均；二者的顺序不能交换。此时没有图级池化，输出仍为 [N,d]。

## 5. 默认形状变化总表

采用 N=32、M=4、d=64、J=4、d_h=16、L=128：

| 步骤 | 形状 |
|---|---|
| 专家表示 H | [32,4,64] |
| 节点对关系 R | [32,32,3] |
| 展平 tokens | [128,64] |
| Q/K/V | [128,4,16] |
| 内容分数 | [4,128,128] |
| 原节点对关系偏置 | [4,32,32] |
| 扩展后偏置 | [4,128,128] |
| RMS 后 code | [4,128,128] |
| 第一次收缩 T | [128,128,16] |
| 第二次收缩 O | [128,4,16] |
| 拼头、残差、归一化后的 Y | [128,64] |
| 恢复节点×专家 | [32,4,64] |
| 专家均值输出 Z | [32,64] |

默认关系条件超网络组合器共有 16,780 个参数：四个 d→d 线性层及其偏置、3→J 关系映射、LayerNorm 的缩放与偏移。这里不包括专家、私有适配器和预测器。

## 6. 四种模式如何区别

| 模式 | 条件编码 | Value 聚合 | 组合器内部跨节点 | 额外返回 |
|---|---|---|---|---|
| hypernetwork_relu | 头轴 RMS | 头收缩→ReLU→key 收缩 | 有 | code [J,L,L] |
| hypernetwork_linear | 头轴 RMS | 头收缩→key 收缩 | 有 | code [J,L,L] |
| standard_attention | key 轴 softmax | 标准单次 key 加权和 | 有 | code [J,L,L] |
| linear_gate | 每节点专家轴 softmax | 原专家表示按权重求和后 LayerNorm | 无 | weights [N,M] |

linear_gate 的“无跨节点”仅指组合器本身；它输入的专家表示已经包含 GNN 邻域信息。关闭 relation_condition 也只移除显式关系偏置，不能据此说整个模型不使用拓扑。

hypernetwork_linear 只是移除中间 ReLU，Q/K 内容分数、RMS、LayerNorm 仍存在；它不是对原输入的整体线性模型。

## 7. 读代码时应保留的边界

1. 默认不做 Top-K、不跳过专家，也没有输出 M 个专家选择概率。
2. relation_gate 缩放关系偏置，不改变图边、不改专家消息传递、不把对应 token 完全屏蔽。
3. 关系条件允许跨节点×跨专家交互，但不证明各专家已解耦成语义因素。
4. 默认输出 Z 是节点潜表示；预测器、任务头和图池化分别在外部。
5. 默认密集分数为 [J,(NM),(NM)]，中间 T 为 [(NM),(NM),d_h]。组合器主要两两交互的计算约为 O((NM)^2 d)，不能称为对节点数的线性复杂度。
6. mask 全 1 只覆盖当前视图；不意味着可以读到被数据协议排除的其他图或其他客户端数据。
7. 当前关系偏置没有直接编码边类型、RWSE、节点身份或因素标签；边属性可能通过专家表示间接影响内容分数。
8. “学习关系条件组合”是明确实现；“获得未见语义组合泛化”仍需正式协议和效果实验。

## 8. 本次核验

为核对解释，直接加载当前 composer.py，采用 N=3、M=2、d=4、J=2 的教学张量：
- 显式循环求和与两次 einsum 的输出最大差值为 0。
- 最终 Z 为 [3,4]；code 为 [2,6,6]。
- None gate 与全 1 gate 功能一致。
- 输入与关系映射的梯度可传播。
- 四种模式的正常／额外输出形状符合上表。
- 默认参数数量为 16,780。

这些检查用于核对公式、形状和调用边界；没有进行新的预训练或真实数据效果实验，也没有修改模型代码。
