# FedG2C 第二阶段：服务器聚合接口边界（待实施）

本文件预留第二阶段设计位置。本轮只实现本地预训练，以下是已讨论的接口约定，不代表可运行代码。

目的：检查参数聚合是否改变客户端学到的组合器关系响应，并在服务器内优化聚合权重。

1. 接收第一阶段 `EdgePredictionClient.get_pretrain_model()`（旧原型为 `LocalPretrainingClient`） 导出的 `experts.*` 与 `composer.*`；配置、专家槽位和关系 schema 必须一致。服务器不接收私有适配器、预测器或动量副本。
2. 随机块模型生成图结构，节点特征独立服从均值 0、标准差 1 的高斯分布，注入共享专家之前。当前 `SharedBackbone.encode_experts()` 已提供连续特征入口。
3. 各本地参考模型编码同一合成图，固定其专家输出，通过 `RelationComposer.forward(..., relation_gate=...)` 扰动组合器关系偏置，读取基准输出及中心有限差分响应。
4. 按可学习权重构造参数空间候选，对同一探针重新执行候选专家编码，再匹配输出和响应。候选专家输出不停止梯度。
5. 服务器内部更新聚合权重并得到最终共享模型，不增加客户端候选往返。

已有关系门控接口只是预留接点。随机块模型探针生成、节点对读出、参考缓存、可微参数组合、权重优化、服务器轮次和对应测试尚未实现。无关系分支或线性门控对照不应伪装产生相同的关系响应。

同一候选的正负扰动共用专家输出；权重更新后必须重新编码。若专家训练时使用边特征，服务器探针如何提供兼容的共享边输入仍需明确配置。随机图可能包含结构组合留出中的禁用模式，正式实验必须审计。

第一阶段接口以 [当前本地预训练设计](../../01_本地预训练_关系条件专家组合学习.md) 为准：逐节点预测器及其结构位置投影留在客户端，共享基座仍只有专家与组合器。后续按本文件扩写目的、数据流、伪代码、公开代码来源及实际接入点。
